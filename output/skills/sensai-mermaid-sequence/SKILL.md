# Mermaid 시퀀스 투영

검증된 호출과 흐름만 시퀀스로 투영하고 추정 메시지를 추가하지 마라.

## 입력

- 현재 미션 루트의 validator 통과 `trace.json`
- AS-IS exact `joins[]`와 비즈니스 흐름 또는 TO-BE `designs[]`와 `requirements[]`
- 산출 대상 `kind: asis` 또는 `kind: tobe`와 출력 경로

## 작업 순서

1. 입력 원장과 요청한 `kind`가 일치하는지 확인하라.
2. 참여자와 메시지마다 원천 식별자와 직접 근거를 먼저 매핑하라.
3. 최대 요구사항 20개, 참여자 12개, 메시지 50개 안에서 `sequenceDiagram`을 작성하라.
4. 메시지에 관련 `REQ-*`, `DESIGN-*` 또는 비즈니스 식별자를 표시하라.
5. `provenance.jq`의 `mermaid` 모드로 역대조하고 `mmdc`로 비어 있지 않은 SVG를 렌더하라.

## 출력

- 현재 미션 산출 경로에 `kind`와 근거 추적이 있는 `Mermaid` 원문을 작성하라.
- 각 메시지와 원천 식별자의 대응, 렌더 결과와 검증기 종료 코드를 기록하라.
- 한도를 넘는 입력은 누락하지 말고 분할 필요 상태로 보고하라.

## 근거 계약

- 근거 계약: 모든 확정 요소에 실제 `path:line`과 하나 이상의 `evidence_ids`를 연결하라.
- 근거가 없으면 `UNKNOWN`, 동적 호출은 `unresolved`, 복수 후보는 `ambiguous` 또는 `many_to_many`, 상충하면 `conflict`를 보존하라.
- 정확 결합이 아닌 호출을 메시지로 승격하거나 `AS-IS`와 `TO-BE`를 섞지 마라.

## 허용 도구와 권한

- 허용된 `jq -e`, `rg`, `mmdc`만 읽기·검증·렌더에 사용하라.
- 스킬 로드는 권한을 추가하지 않는다. 현재 대상 저장소 안의 명시적으로 선택된 원본은 읽기 전용으로만 읽을 수 있다. 비밀 경로와 대상 저장소 밖은 읽지 말고, 쓰기는 현재 미션 루트 안에서 주 에이전트의 허용 경로에만 수행하라.
- 사용자 문자열을 셸 문법으로 실행하지 말고, 비밀 정보와 전역 설정을 읽지 마라.

## 실패 처리

- 근거 추적 불일치, 한도 초과 또는 `Mermaid` 렌더 실패를 차단 사유로 기록하라.
- 원천 식별자 역대조나 검증기가 실패하면 부분 산출물을 완료로 표시하지 않는다.
