# UI 정의 투영

검증된 원장을 UI 정의서로 투영하고 산출물을 새로운 진실 원장으로 취급하지 마라.

## 입력

- 현재 미션 루트의 validator 통과 `trace.json`
- `AS-IS`는 `frontends[]`와 관련 비즈니스 사실을, `TO-BE`는 `designs[]`와 `requirements[]`를 사용하라.
- 산출 대상 `kind: asis` 또는 `kind: tobe`와 출력 경로

## 작업 순서

1. 입력 원장과 요청한 `kind`가 일치하는지 확인하라.
2. 화면별 원천 식별자, 근거 식별자와 직접 근거를 먼저 매핑하라.
3. 검증된 화면·동작만 한국어 설명과 Mermaid 와이어프레임으로 투영하라.
4. `provenance.jq`의 `ui` 모드로 모든 식별자와 원천을 역대조하라.
5. `mdq`로 문서 구조를 확인하고 `mmdc`로 비어 있지 않은 SVG를 렌더하라.

## 출력

- 현재 미션 산출 경로에 한국어 `Markdown UI` 정의서를 작성하라.
- 문서에 `kind`, 원천 식별자, 근거 식별자와 실제 근거 추적을 포함하라.
- 렌더 결과와 검증기 종료 코드를 검증 영수증에 기록하라.

## 근거 계약

- 근거 계약: 모든 확정 요소에 실제 `path:line`과 하나 이상의 `evidence_ids`를 연결하라.
- 근거가 없으면 `UNKNOWN`, 동적 요소는 `unresolved`, 복수 후보는 `ambiguous` 또는 `many_to_many`, 상충하면 `conflict`를 보존하라.
- `AS-IS`와 `TO-BE`를 섞거나 원장에 없는 화면을 발명하지 마라.

## 허용 도구와 권한

- 허용된 `jq -e`, `rg`, `mdq`, `mmdc`만 읽기·검증·렌더에 사용하라.
- 스킬 로드는 권한을 추가하지 않는다. 현재 미션 루트 밖을 읽거나 쓰지 말고, 쓰기는 주 에이전트의 허용 경로에만 수행하라.
- 사용자 문자열을 셸 문법으로 실행하지 말고, 비밀 정보와 전역 설정을 읽지 마라.

## 실패 처리

- 근거 추적 불일치, `Markdown` 구조 오류 또는 `Mermaid` 렌더 실패를 차단 사유로 기록하라.
- 원천 식별자 역대조나 검증기가 실패하면 부분 산출물을 완료로 표시하지 않는다.
