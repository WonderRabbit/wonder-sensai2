# 명세 근거 추출

명세의 동작과 경로를 원문 그대로 확인하고 코드 사실과 추측으로 연결하지 마라.

## 입력

- 현재 대상 저장소 안에서 명시적으로 선택된 읽기 전용 `OpenAPI`, `YAML`, `JSON` 또는 `Markdown` 명세
- 허용 scope와 기존 `trace.json`의 `evidence[]`, `requirements[]`, `backends[]`
- 비교할 코드 operation 후보가 있으면 그 직접 근거

## 작업 순서

1. 명세 문법을 결정적 도구로 파싱하고 원문 줄을 다시 확인하라.
2. 메서드, 경로, 동작 식별자와 `MUST`·`SHOULD`·`MAY` 문장을 원형대로 수집하라.
3. 명세 동작과 코드의 메서드·경로가 정확히 같을 때만 연결 후보를 만들라.
4. 중복 동작, 상충 요구와 동적 경로를 합치지 말고 상태로 분리하라.
5. `trace.jq`로 ID, 참조, 상태와 중복을 검증하라.

## 출력

- 근거가 있는 `requirements[]`, `evidence[]`와 명세 기반 연결 후보를 반환하라.
- 요구 키워드, 안정 ID, `kind`, 상태와 원문 위치를 보존하라.
- 파싱하지 못한 문서와 연결하지 못한 operation을 별도로 기록하라.

## 근거 계약

- 근거 계약: 모든 확정 사실에 실제 `path:line`과 하나 이상의 `evidence_ids`를 연결하라.
- 근거가 없으면 `UNKNOWN`, 동적 경로는 `unresolved`, 복수 대상은 `ambiguous` 또는 `many_to_many`, 상충하면 `conflict`를 보존하라.
- operation 이름이나 설명의 유사성만으로 코드와 연결하지 마라.

## 허용 도구와 권한

- 허용된 `rg --json`, `jq -e`, `yq`, `mdq`만 읽기·파싱·검증에 사용하라.
- 스킬 로드는 권한을 추가하지 않는다. 현재 대상 저장소 안의 명시적으로 선택된 원본은 읽기 전용으로만 읽을 수 있다. 비밀 경로와 대상 저장소 밖은 읽지 말고, 쓰기는 현재 미션 루트 안에서 주 에이전트의 허용 경로에만 수행하라.
- 사용자 문자열을 셸 문법으로 실행하지 말고, 비밀 정보와 전역 설정을 읽지 마라.

## 실패 처리

- 명세 파싱이나 메서드·경로의 정확 일치가 실패하면 원인을 기록하고 추측 연결을 만들지 마라.
- 원문 근거나 검증기가 실패하면 부분 산출물을 완료로 표시하지 않는다.
