# React 경로 추적

`React`가 입증된 범위에서만 화면 경로와 동작 후보를 수집하고 정확 결합을 검증하라.

## 입력

- 현재 미션 루트와 React 사용·버전을 입증한 매니페스트 `path:line`
- 허용 범위의 경로, 컴포넌트, 동작 원문
- 기존 `trace.json`의 `evidence[]`, `frontends[]`, `joins[]`

## 작업 순서

1. React와 버전의 직접 근거를 확인하라. 입증되지 않았으면 적용하지 마라.
2. 구조 검색으로 경로, 컴포넌트, 동작 후보와 선언·사용 줄을 수집하라.
3. 상수 route는 선언과 소비 양쪽을 확인하고, 동적 경로는 확정하지 마라.
4. 화면과 서버 양쪽 직접 근거가 같은 메서드와 경로를 지지할 때만 정확 결합을 만들라.
5. `trace.jq`로 ID, 참조, 상태와 중복을 검증하라.

## 출력

- 근거가 있는 `frontends[]`, 관련 `conventions[]`, `joins[]` 후보를 반환하라.
- 각 사실에 안정 식별자, `kind: asis`, 상태와 근거 식별자를 포함하라.
- 사용한 React 버전 근거와 적용하지 못한 범위를 함께 기록하라.

## 근거 계약

- 근거 계약: 모든 확정 사실에 실제 `path:line`과 하나 이상의 `evidence_ids`를 연결하라.
- 근거가 없으면 `UNKNOWN`, 동적 경로는 `unresolved`, 복수 대상은 `ambiguous` 또는 `many_to_many`, 상충하면 `conflict`를 보존하라.
- 후보 경로나 이름 유사성을 근거로 결합을 승격하지 마라.

## 허용 도구와 권한

- 허용된 `fd`, `rg --json`, `sg --json`, `jq -e`만 읽기·검증에 사용하라.
- 스킬 로드는 권한을 추가하지 않는다. 현재 미션 루트 밖을 읽거나 쓰지 말고, 쓰기는 주 에이전트의 허용 경로에만 수행하라.
- 사용자 문자열을 셸 문법으로 실행하지 말고, 비밀 정보와 전역 설정을 읽지 마라.

## 실패 처리

- React 사용이나 버전이 입증되지 않으면 적용 중단 사유를 반환하고 강제 매핑하지 마라.
- 정확 결합 또는 검증기가 실패하면 부분 산출물을 완료로 표시하지 않는다.
