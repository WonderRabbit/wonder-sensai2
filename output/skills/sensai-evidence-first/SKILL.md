# 근거 우선 판정

검증된 사실과 모델 후보를 분리하고, 근거 없는 값을 정규 원장에 승격하지 마라.

## 입력

- 현재 대상 저장소 안에서 명시적으로 선택된 읽기 전용 원본과 현재 미션 루트
- 검증할 주장, 후보, 안정 ID와 원문 파일
- 기존 `trace.json`이 있으면 그 원장의 `evidence[]`와 상태

## 작업 순서

1. 입력 경로가 현재 미션 범위 안인지 확인하라.
2. 후보를 원문에서 다시 찾아 실제 줄과 관찰값을 확인하라.
3. 한 근거가 한 사실을 직접 지지하는지 판정하고 안정 `E-*` ID를 부여하라.
4. 양쪽 근거가 있는 연결만 `exact`로 기록하라. 이름 유사성만으로 연결하지 마라.
5. 결정적 검증기로 식별자 중복, 끊어진 참조와 상태를 검사하라.

## 출력

- `evidence[]`에 안정 ID, `kind`, 경로, 줄, `path_line`을 기록하라.
- 사실 엔티티의 `evidence_ids`로 근거를 역참조하라.
- 모순과 미확정 항목을 별도 상태와 다음 확인 대상으로 남겨라.

## 근거 계약

- 근거 계약: 모든 확정 사실에 실제 `path:line`과 하나 이상의 `evidence_ids`를 연결하라.
- 근거가 없으면 `UNKNOWN`, 동적으로만 결정되면 `unresolved`, 복수 후보면 `ambiguous` 또는 `many_to_many`, 상충하면 `conflict`를 보존하라.
- 후보를 검증기 통과 전 정규 사실이나 입학 완료 상태로 승격하지 마라.

## 허용 도구와 권한

- 허용된 `fd`, `rg --json`, `sg --json`, `jq -e`, `yq`만 읽기·검증에 사용하라.
- 스킬 로드는 권한을 추가하지 않는다. 현재 대상 저장소 안의 명시적으로 선택된 원본은 읽기 전용으로만 읽을 수 있다. 비밀 경로와 대상 저장소 밖은 읽지 말고, 쓰기는 현재 미션 루트 안에서 주 에이전트의 허용 경로에만 수행하라.
- 사용자 문자열을 셸 문법으로 실행하지 말고, 비밀 정보와 전역 설정을 읽지 마라.

## 실패 처리

- 경로, 줄, 원문 또는 검증 결과를 재현할 수 없으면 실패 상태와 누락 입력을 기록하라.
- 검증기가 실패하거나 직접 근거가 없으면 부분 산출물을 완료로 표시하지 않는다.
