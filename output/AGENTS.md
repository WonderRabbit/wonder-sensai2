# wonder-sensai OpenCode 실행 계약

이 파일은 설치된 OpenCode 하네스의 실행 행동 계약이다. 설정 디렉터리에서 자동으로 읽힌다고 가정하지 않는다. 같은 불변조건은 `opencode.json`의 권한, 에이전트 지침, 명령 본문, 스킬 본문에도 반복하고, 서로 충돌하면 더 제한적인 규칙을 적용한다. 사람이 읽는 제목·설명·지침·표시명은 한국어로 작성하되 기계 키, 스키마 필드, 공급자·모델 식별자, 경로, 명령·스킬 이름, 안정 식별자, 열거형, 이유 코드와 문법은 번역하지 않는다.

## 미션과 진실 원장

- 모든 미션 상태와 산출물은 대상 저장소의 `docs/analysis/missions/<mission-id>/` 아래에만 둔다.
- `sensai-analysis-lead`만 정규 미션 상태를 쓰는 단일 작성자다. `sensai-evidence-peer`는 읽기 전용이며 편집, 최종 판정, 재위임을 하지 않는다.
- 진실 우선순위는 검증된 `trace.json` > 검증된 `progress.json` > 파생 `status.md`와 세션 할 일이다.
- 모든 사실은 안정 ID와 `path:line` 근거를 가져야 한다. 근거가 없으면 채우지 말고 `UNKNOWN`, `unresolved`, `ambiguous`, `many_to_many`, `conflict` 중 맞는 상태를 보존한다.
- 이름 유사성만으로 연결하지 않는다. 충돌과 규약 위반을 산출물에서 숨기지 않는다.

## 사람 승인 게이트

- F0: 미션 범위와 계획을 사람이 승인하기 전 분석을 시작하지 않는다.
- F3: AS-IS `trace.json`과 4종 투영, 위반과 충돌을 사람이 승인하기 전 TO-BE 설계로 넘어가지 않는다.
- F5: TO-BE 5종 투영과 결정적 검증 영수증을 사람이 승인하기 전 완료로 표시하지 않는다.
- 위반의 예외 승인과 모델 입학은 명시적인 사람 판정이 필요하다. 모델이 사람 승인을 생성하거나 추정할 수 없다.

## 도구와 권한 경계

- 주 에이전트의 쓰기는 현재 미션 루트에 한정한다. 근거 에이전트의 편집·쓰기와 다른 에이전트 재위임은 금지한다.
- 셸은 정해진 결정적 CLI와 읽기·검증 명령에만 사용한다. 사용자 텍스트를 명령으로 실행하거나 파이프, 리다이렉션, 명령 치환으로 권한 경계를 우회하지 않는다.
- 비밀 정보, 자격 증명, 실제 `HOME`, 전역 OpenCode 설정, 미션 밖의 파일을 읽거나 수정하지 않는다.
- 스키마와 `jq` 검증기의 실패를 지침 판단으로 덮어쓰지 않는다. 실패 시 부분 산출물을 완료로 표시하지 않는다.
- 실시간 모델 호출, 외부 공유, 전역 설정 변경, 임의 플러그인·`MCP`·사용자 정의 도구 추가는 별도 승인 없이는 금지한다.
- 이 지침과 OpenCode `permission`은 행동 경계와 승인 정책이며 운영체제 샌드박스가 아니다. 파일시스템·프로세스·네트워크 격리를 제공한다고 주장하지 않는다.

## 상태의 한계

현재 공급자·모델 값은 설정 적재 기준선일 뿐이다. 실시간 응답, 도구 호출, 구조화 출력, 위임은 `MODEL_ADMISSION_UNVERIFIED`이며 성공으로 주장하지 않는다. macOS 결정적 검증이 현재 로컬 게이트이고 Windows는 사용자가 최종 릴리스 후보에서 수행할 영수증이므로 `WINDOWS_RECEIPT_PENDING`을 유지한다.

`opencode.json`의 `sensai-ollama` 공급자는 로컬 `http://localhost:11434/v1`만 사용한다. `apiKey` 값 `ollama`는 OpenAI 호환 공급자 형식을 만족시키는 비밀 아닌 고정 자리표시자이며 실제 자격 증명이 아니다. 환경 변수나 실제 비밀값으로 바꾸거나 다른 호스트와 결합하지 않는다.
